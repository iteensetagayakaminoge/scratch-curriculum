# 1. このタスクの目的

`lesson-spec.md` に定義された教材仕様と、`lesson-manifest.json` に記録されたScratch実装情報をもとに、

**生徒が自分で読みながらScratch作品を完成できるWEB教材**

を制作する。

WEB教材は動画を見る方式ではなく、

* 読む
* 見る
* Scratchで作る
* 動かす
* 確認する
* 戻る
* 改造する

という学習体験を支援する。

# 3. Antigravityの担当範囲

Antigravityは、

**教材内容そのものではなく、生徒が使う教材体験を設計・実装する。**

* WEB教材ページ
* STEP表示

# 4. 最重要の役割分担

教材として、

**「何を・どの順番で学ぶか」**

# 6. 着手前エスカレーション

以下の場合は制作開始または継続を停止し、チャッピーへ確認する。

* STEP内容に矛盾がある
* 生徒向け説明に必要な情報が不足している
* lesson-specとlesson-manifestが一致しない
* Scratch作品とlesson-specが一致しない
* Scratch作品とlesson-manifestが一致しない
* 素材が不足している
* 表示内容と完成条件が一致しない
* 低学年には理解困難と思われる
* 1STEPの情報量が著しく多い
* 約400px幅で実用的に表示できない
* 技術的にWEB実装が困難
* 既存WEB構成と重大な衝突がある

独自修正は行わない。

# 7. STEP分割計画

Antigravityは、lesson-specのSTEPをWEB上で分割する場合、事前に `step_split_plan` を作成する。

例：

```text
STEP 1
→ WEB 1-1
→ WEB 1-2

STEP 2
→ WEB 2-1

STEP 3
→ WEB 3-1
→ WEB 3-2
→ WEB 3-3
```

分割の目的は、

* 情報量削減
* 1画面1アクション
* 低学年の理解向上
* 動作確認の挿入

とする。

STEP順序そのものは変更しない。

---

# 8. WEB教材の基本構造

原則として以下の流れを使用する。

```text
タイトル

この作品でできること

今日使う技

必要素材

素材ダウンロード

STEP 1

STEP 2

STEP 3

...

完成！

チャレンジ

オリジナル改造

先生チェック
```

---

# 9. 1画面1アクション

WEB教材では、

**1画面 / 1カード = 1つの主要操作**

を原則とする。

避ける例：

> ブロックを出して、数字を変えて、次に変数を作って、緑の旗を押そう。

推奨：

1. ブロックを出そう
2. 数字を変えよう
3. 動かしてみよう

# 12. Scratchブロック表示

Scratchブロック表示は、第一候補として `scratchblocks` 等によるSVG描画を利用する。

目的：

* Scratchに近い見た目
* 修正容易性
* 量産性
* Git管理
* テキストベース生成

SC001では、

* 日本語表示
* 狭い画面
* 数値表示
* 変数表示
* 複数ブロック連結
* SVGサイズ

を確認する。

---

# 13. Scratchブロック補足表示

* 数値ハイライト

とする。

* 難しい漢字を多用しない

する。

全漢字へのルビは必須としない。

# 23. 達成フィードバック

**「できた！」**

等の達成確認を表示してよい。

# 24. 動作確認
